# 우주스테이 앱(PMS) 디자인 시스템

사장님이 매일 쓰는 앱 화면(`/app`)의 디자인 규칙입니다.
랜딩페이지(컬러 시안 C)와 **같은 브랜드로 보이되, 데이터를 빽빽하게 다루는 업무 화면**에 맞게 크기·간격만 줄였습니다.
2026-11-16부터 [PMS-DESIGN-V2.md](PMS-DESIGN-V2.md)("AI로 만든 티" 빼기) 방향을 따릅니다. 이 문서와 V2가 다르면 V2가 맞습니다.

- 토큰: `src/ui/pms/styles/pms-tokens.css` (랜딩 `src/ui/styles/tokens.css` 를 그대로 물려받음)
- 부품: `src/ui/pms/components/` · 화면 틀: `src/ui/pms/shell/` · 화면: `src/ui/pms/screens/`
- 미리보기: `pnpm dev` → http://localhost:3000/app

## 1. 원칙

1. **브랜드는 랜딩과 같다.** 남색 `#1C2B46` + 주황 `#FF5800`, Pretendard 하나. 새 색을 만들지 않는다.
2. **주 동작은 남색 단색, 주황은 표시용.** 주황은 버튼 면에 쓰지 않는다. 쓰는 곳은 지금 메뉴 막대, 저장 전 고친 칸, 안 읽은 알림 점, 포커스 고리, 별점뿐.
3. **그림자 대신 선과 면.** 패널은 1px 선(`--pm-line`). 그림자는 떠 있는 것(메뉴·모달·저장 바·토스트)에만.
4. **꾸밈 없이 말로.** 제목 위 영문 대문자 꼬리표, 반짝이(✦) 아이콘, 그라데이션, 가운뎃점으로 이은 메타를 쓰지 않는다. "답글 초안", "다시 쓰기"처럼 하는 일을 쓴다.
5. **숫자는 고정폭.** 금액·재고·날짜에는 `.num`(tabular-nums)을 붙여 열이 흔들리지 않게.
6. **상태는 글자 + 색 쌍으로.** 색만으로 구분하지 않는다 (판매/마감, 정상/재인증 필요 처럼 글자를 같이).

## 6. 화면 패턴

### 홈 (F0-12)

제목 자리에 날짜(`11월 16일 월요일`) → 요약 띠 3칸(오늘 예약매출 · 답글 기다리는 리뷰 · 7일 안 정산 예정) → 채널별 매출 막대(남색 한 색, 1위만 진한 남색) · 정산 예정(D-n) · 답글 기다리는 리뷰 · 채널 연동 상태. 연동이 끊긴 채널이 있으면 맨 위 빨간 띠로 알림.

### 리뷰 관리 (F1-01 ~ F1-07)

알약 탭(전체·미답변·긍정·개선요청 + 건수) → 왼쪽 리뷰 목록(패널 하나를 선으로 나눔) / 오른쪽 상세(고정). 상세에는 리뷰 원문 → **답글 초안**(키 없이 만든 경우 옆에 회색 "기본 문장", 반영한 키워드 태그 + 고칠 수 있는 입력칸, "다시 쓰기"). 자동 게시 채널은 `○○에 게시하기`, 아닌 채널은 `복사하고 게시 완료로 표시`. 실명·연락처가 든 리뷰는 "확인 필요" 경고.

### 요금·재고 (기능정의서 미포함 · 제안)

온다 호텔 익스트라넷 분석을 반영한 그리드. 객실 줄(판매 가능 수) → 요금제별 판매 스위치 · 재고 · 요금 → 자동 계산 요금제(기준 요금제 ±원/%).

- 고친 칸은 연한 주황 + 아래 주황 선, 하단에 떠 있는 **저장 바**(건수 · 오류 · 모두 되돌리기 · 변경 내용 확인).
- 확인 창에는 **판매상태 변경까지 모든 변경**과 자동 계산 요금제에 따라 바뀌는 값을 같이 보여준다 (온다는 판매상태를 목록에서 빼먹음).
- **빈칸 = 미입력**으로 저장 가능 (온다는 0원 저장이 막혀 값을 비울 수 없었음). 1,000원 미만 요금은 빨간 칸 + 저장 막음.
- 기간 일괄 변경: 기간 · 요일 칩(매일/일–목/금–토) · 요금제 · 바꿀 값(비우면 그대로).

### 현장 업무 (F7 · 사업소개서 '내부 업무시스템')

객실 칸은 **왼쪽 상태 막대 + 상태 글자** 쌍으로 구분 (색만으로 구분하지 않기). 손이 가야 하는 순서로 정렬: 청소 필요(`bad`) → 청소 중(`warn`) → 점검 대기(`info`) → 판매 가능(`ok`) → 투숙 중(`neutral`) → 판매 중지(회색 사선 `--pm-closed`). 주황은 쓰지 않는다 — 안 읽은 글 점에만. 상태 필터 칩의 색 막대는 칸 왼쪽 막대와 같은 범례. 칸을 누르면 다음 단계 버튼(퇴실 처리 → 청소 시작 → 청소 완료 · 점검 요청 → 점검 완료 · 판매 가능)이 크게 하나, 그 아래 직접 고르기 · 메모 · 최근 기록. 휴대폰에서는 칸에 호수와 상태만.

경고·주의 띠(연동 끊김, 최저임금 미달 등)는 `--pm-bad-bg` 면 + 굵은 대상 이름 + 해결 버튼 순서로 통일.

### 차트

선 그래프는 남색 2px **곧은 선** 하나 (매끈한 곡선은 없는 오르내림을 만든다). 면 그라데이션 없이 점마다 작은 빈 점, 이번 달만 채운 점. 점 위에 `9,101만` 처럼 만 단위 값, 휴대폰은 홀수 달 글자만 11px. 축 글자는 `--pm-muted`. 막대는 남색 한 색(강조 하나만 진하게), 모서리 2px.

| 표 칸                            | `formatNumber`     | 4,820,000 (머리에 `(원)`)       | 칸마다 ₩·원            |
| 좁은 자리 (차트 라벨, 다음 입금) | `formatWonCompact` | 9,101만 · 310만 원              | 91.0M, 2.74M           |
| 시간                             | `formatHours`      | 91시간 · 161.5시간              | 161.9h, 7h             |
| 증감                             | `Stat delta`       | +12.3% (색 글자)                | 초록 알약              |
| 날짜                             | `formatShortDate`  | 11.21 (토) · 직원 기록 7일 (금) | 11.7 / 11.19 섞어 쓰기 |

비율은 한 화면 안에서 같은 자릿수로 (27% 와 15.3% 를 섞지 않는다). 숫자 칸에는 늘 `.num`.

### 7.2 표기

- **가운뎃점**: 낱말 사이에 붙여 쓴 나열(`예약·리뷰·정산`)은 괜찮다. 띄어 쓴 `·` 로 메타를 잇지 않는다 → 한 가지만 쓰거나 쉼표·`›`. 버튼 글자에는 가운뎃점을 쓰지 않는다(`내 근무와 급여`, `호수와 타입 고치기`). 메뉴 이름(`요금·재고`, `직원·권한`, `구독·결제`)은 고유 이름이라 그대로. 데이터에 섞여 온 `·` 목록은 `plainList()` 로 쉼표.
- **조사**: 강조한 숫자·날짜 뒤 조사는 붙인다 — `2026.12.20까지`, `₩106,000이`.
- **말투**: 사장님·직원·운영자 화면 모두 해요체. 법적 동의 문구(`동의합니다`)만 예외.
- **꼬리표**: 영문 대문자 꼬리표 없음. 운영자 화면 상단은 `운영팀 전용`.

### 7.4 상태 표시

- 평소 상태(연결됨, 사용 중, 판매 중)는 **회색 글자**. 배지는 문제·진행 중(연동 끊김, 결제 실패, 초대 보냄, 수집 중)에만.
- 주의(`warn`)는 호박색 — 브랜드 주황 글자와 헷갈리지 않게. 낮은 별점은 `bad` 또는 굵은 남색.
- 경고 띠의 버튼은 `alert`, 표 줄 안 버튼은 `ghost`/글자 버튼. 남색 주 버튼은 화면당 하나(모달 안은 모달당 하나).
- 입력 오류는 `aria-invalid="true"` → 빨간 테두리 + 아래 오류 문장(`aria-describedby`).
- 손가락: `pointer: coarse` 에서 누르는 것은 44px 이상, 직원 화면의 주 동작은 48px 전체 폭.

## 8. 작업 규칙

- 블록 이름은 `pm-`(공통 부품) 또는 화면 약자(`dash-`, `rv-`, `rt-`)로 시작 — 랜딩 블록과 겹치지 않게.
- 색·크기는 `var(--pm-*)` 만. 랜딩 토큰을 직접 쓰지 말고 pms-tokens.css 에 이름을 붙여서 쓴다.
- 데이터는 지금 `src/infrastructure/pms/sample-data.ts` 의 예시값. 실제 연동 시 `PmsRepository` 구현만 바꾸면 화면은 그대로.
- 앱은 `/app` 아래 별도 root layout(`src/app/(pms)/app/layout.tsx`)이고, 사이드바가 있는 화면은 `(main)`, 로그인·온보딩은 `(auth)` 그룹이다. 그래서 홈페이지 CSS와 섞이지 않고, 검색 노출을 막아 두었다(`robots: noindex`).
