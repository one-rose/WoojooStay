# 여러 업장 통합 현황 (F8 · 2026-11-16 대표 요청)

> "대표가 운영 중인 사업장이 10개이니, 통합적인 현황이 중심이 되어서 원스톱으로 관리의 편의성을 높여야 함 — 핵심"

## 목표

업장을 여러 곳 운영하는 사장님(실증 파트너 한소영 대표: 10곳)이 로그인하면 **업장 하나의 홈이 아니라 전체 업장 현황**을 먼저 본다.
어디에 손이 가야 하는지 한 화면에서 찾고, 누르면 그 업장 화면으로 바로 들어간다. 업장을 오가는 데 로그아웃이 필요 없다.

## 화면

- 행을 누르면 그 업장으로 전환하고 그 업장 홈(`/app`)으로. 셀 안 링크(미답변 수 → 리뷰, 청소 → 현장 업무, 채널 → 채널 연동)는 그 업장으로 전환하면서 해당 화면으로.
- 숫자 열은 오른쪽 정렬·고정폭. 표 머리 클릭으로 정렬. 휴대폰(≤720px)은 표 대신 업장별 카드 목록(업장명, 오늘 매출, 미답변, 문제 배지).
- 디자인은 docs/PMS-DESIGN-V2.md 그대로 (요약 띠, 남색 주 버튼, 상태 배지는 상태에만, 꼬리표·반짝이 없음).

### 2. 업장 전환 (모든 화면)

- 사이드바 맨 위 업장 이름이 버튼이 된다 → 열리는 목록: 맨 위 "전체 현황", 그 아래 업장들(이름 + 문제 있으면 작은 빨간 점), 검색 칸(업장 5곳 이상일 때).
- 업장을 고르면 쿠키(업장 ID)를 바꾸고 지금 보던 메뉴 그대로 그 업장 화면을 연다 (예: 리뷰 관리에서 바꾸면 그 업장 리뷰 관리).
- 사이드바 메뉴 맨 위에 "전체 현황" (업장 2곳 이상일 때만).
- 업장이 1곳이면 지금과 똑같이 동작한다 (전환 버튼·전체 현황 메뉴 없음).

## API

`GET /api/v1/portfolio` (로그인 사용자, 본인이 OWNER·MANAGER 인 업장만. STAFF 만인 업장은 제외)

```jsonc
{
  "date": "2026-11-16",
  "properties": [{
    "id": "…", "name": "RAINBOW HOTEL", "type": "HOTEL", "rooms": 48, "role": "OWNER",
    "today": { "sales": 4820000, "bookings": 31, "yesterdaySales": 4288000 },
    "month": { "sales": 98200000, "prevToDate": 91000000 },
    "reviews": { "unanswered": 5, "lowRated": 2 },
    "settle7": 12640000,
    "rooms": { "ready": 12, "dirty": 9, "cleaning": 3, "inspect": 2, "occupied": 24, "outOfOrder": 1, "staleDirty": 4 },  // staleDirty: 청소 필요로 2시간 넘게
    "staff": { "onDuty": 3, "missingClockOut": 1 },
    "channels": { "connected": 4, "error": 0, "authExpired": 0 },
    "billing": { "status": "TRIAL" | "ACTIVE" | "PAST_DUE" | "CANCELLED" },
    "alerts": [{ "kind": "CHANNEL_AUTH" | "CHANNEL_ERROR" | "NO_CHANNEL" | "LOW_RATED" | "STALE_DIRTY" | "MISSING_CLOCK_OUT" | "PAYMENT_FAILED", "message": "여기어때 연동이 끊겼어요", "link": "/app/settings/channels" }]
  }],
  "totals": { /* today·month·reviews·settle7 합계 */ }
}
```

- 업장 수만큼 반복 쿼리하지 말고 `groupBy`/집계 쿼리로 (10곳 이상에서도 1초 안).
- alerts 정렬: 채널 끊김 > 결제 실패 > 저평점 미답변 > 청소 지연 > 퇴근 누락 > 채널 없음.

## 체험 모드 (서버 없이 배포)

Vercel 체험 모드에서도 **업장 10곳**이 보여야 한다 (대표님이 이 화면으로 확인함).

- 예시 데이터에 10곳: RAINBOW HOTEL, 저스트슬립호텔 대전유성온천점, 루오 호텔 대흥점, 브라운도트 호텔 대덕점, N7 호텔 + 대전·충청 5곳(예시 이름). 업장마다 숫자·문제를 다르게.
- 체험 모드 로그인 → `/app/overview`. 업장을 고르면 그 업장 이름으로 기존 예시 화면을 보여준다 (데이터 내용은 공통 예시라도 이름·객실 수는 그 업장 것).
- 날짜는 기존 demo-clock 으로 오늘 기준.

## 개발용 시드

`pnpm db:seed:reset` 결과에서 한소영(010-2000-0000) 계정이 **10곳**의 OWNER. 기존 실증 5곳(지금 다른 계정 소유인 루오·브라운도트·N7 포함)을 한소영 소유로 옮기고 5곳을 더 만든다. 업장마다 채널 수·연동 상태·객실 상태·미답변·직원 근무를 다르게.
